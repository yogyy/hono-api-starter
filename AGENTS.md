# AGENTS.md

Single Cloudflare Worker (Wrangler) exposing a Hono API under `/api`, backed by
Cloudflare D1 (SQLite) through Drizzle ORM, with auth handled by Better Auth.
Bun is the package manager (`bun.lock` is the only committed lockfile).

## Commands

```bash
bun install
bun run dev         # wrangler dev; http://localhost:8787/api/*
bun run deploy      # wrangler deploy --minify
bun run cf-typegen  # wrangler types --env-interface=CloudflareBindings
bun run lint        # oxlint; warnings do not fail the run
bun run lint:fix
bun run fmt         # oxfmt
bun run fmt:check
```

Database commands are not wired into `package.json`; call the tools directly:

```bash
npx drizzle-kit generate                 # src/db/schema.ts -> drizzle/<ts>_<name>/
npx wrangler d1 migrations apply DB --local
npx wrangler d1 migrations apply DB --remote
npx drizzle-kit studio                   # uses dbCredentials in drizzle.config.ts
```

- `src/index.ts` is the only Worker entrypoint; `wrangler.jsonc` sets it as
  `main`.
- Scripts are runner-agnostic, so `npm run <script>` works too. `pnpm` is not
  installed, and `pnpm-workspace.yaml` only carries build-approval settings for
  `esbuild`/`workerd` — it is not a workspace definition.
- No test framework and no typecheck script. `oxlint` only lints;
  `npx wrangler deploy --dry-run` checks bundling, not types.
- oxfmt runs with `printWidth: 80` and sorted imports (see `.oxfmtrc.json`). It
  ignores `.agents/**`, `.claude/**`, `agent/**`, `drizzle/meta/**`, and
  `worker-configuration.d.ts`. Run `npx oxfmt <path>...` on touched files.

## Setup and env

- `wrangler.jsonc` has a placeholder `database_id`
  (`00000000-0000-0000-0000-000000000000`). Run
  `npx wrangler d1 create hono-d1-starter-db` and paste the real ID before
  deploying.
- `.dev.vars` is gitignored and supplies `BETTER_AUTH_SECRET` and
  `BETTER_AUTH_URL`. `.dev.vars.example` shows the shape — note it currently
  contains a real-looking secret, so rotate it before that file is public.
- D1 is bound as `DB`; `wrangler.jsonc` sets `migrations_dir = "drizzle"`.
- `worker-configuration.d.ts` is generated by `wrangler types`. Regenerate with
  `bun run cf-typegen` after changing bindings or local secrets. It defines the
  `Cloudflare.Env` interface that all `Env` types derive from.
- `compatibility_date` is `2026-10-30` with `nodejs_compat` enabled. Keep it on
  while Better Auth is a dependency.

## Architecture

- `src/index.ts` creates one `Hono<{ Bindings: Cloudflare.Env }>()` with
  `.basePath("/api")`, calls `showRoutes(app)` for startup route logging, and
  exports the app as default.
- `src/db/index.ts` exports `getDb(d1)` returning `drizzle(d1)`. Create it per
  request; there is no module-level pool.
- `src/db/schema.ts` is the Drizzle schema and the source of truth: `user`,
  `session`, `account`, `verification`, plus `authRelations` built with
  `defineRelationsPart`. Timestamps are `integer(..., { mode: "timestamp_ms" })`
  with SQL defaults, not `integer` seconds.
- `src/lib/auth.ts` exports `auth(env)`, a factory that builds a fresh
  `betterAuth` instance per call and wires `drizzleAdapter` with
  `provider: "sqlite"`. The adapter is imported from
  `@better-auth/drizzle-adapter/relations-v2`, which is what the relations-style
  schema expects.
- `src/lib/options.ts` holds `betterAuthOptions`: `emailAndPassword` enabled and
  the `bearer()` plugin loaded.
- `src/session-middleware.ts` exports `sessionMiddleware`, a
  `createMiddleware` that calls `api.getSession({ headers })` and stores the
  result in the `session` variable as `Session | null`.
- Responses are JSON-shaped. The unauthenticated case returns
  `{ error: "Unauthorized" }` with status 401.

## API surface

All routes are under `/api` because of the base path.

| Route          | Method    | Behavior                                                                                                   |
| -------------- | --------- | ---------------------------------------------------------------------------------------------------------- |
| `/api/auth/*`  | GET, POST | Forwarded to the Better Auth handler                                                                       |
| `/api/`        | GET       | `sessionMiddleware`, logs the session, returns `Hello Hono!` text                                          |
| `/api/hello`   | GET       | `sessionMiddleware`; 401 JSON without a session, else `{ message: "Hello, <name>." }`                      |
| `/api/get-acc` | GET       | Dev scratch endpoint: signs up a hardcoded `user@example.com` via `api.signUpEmail` and returns the result |

## Database workflow

- Edit `src/db/schema.ts`, then run `npx drizzle-kit generate`. drizzle-kit v1
  writes one `drizzle/<timestamp>_<name>/` folder containing `migration.sql` and
  `snapshot.json`. Commit the whole folder; there is no `drizzle/meta/` journal
  in this layout.
- Apply with `npx wrangler d1 migrations apply DB --local` (or `--remote`).
- Do not use `drizzle-kit migrate` or `drizzle-kit push`. D1 tracks migrations
  itself, so Wrangler must apply them.
- `drizzle.config.ts` points at the local miniflare SQLite file for
  `drizzle-kit studio` only. Do not treat it as the app's connection config.
- Local D1 state lives in `.wrangler/state`; deleting it resets local data.
- There is no seed file and no migration runner script any more; both were
  removed when the project moved to D1.

## Known rough edges

These are real, current-state issues — do not assume the code is clean here.

- `src/db/auth-schema.ts` is byte-for-byte identical to `src/db/schema.ts` and
  is imported nowhere. `schema.ts` is the one `drizzle.config.ts` and
  `src/lib/auth.ts` use.
- `src/controllers/` is empty.
- `betterAuthOptions.basePath` is `/api`, but the handler is mounted at
  `/api/auth/*`. Better Auth strips `basePath` before matching, so the HTTP
  routes under `/api/auth/*` may not resolve even though the programmatic
  `auth(env).api.*` calls (as used by `/api/get-acc`) work. Verify before
  relying on the HTTP auth endpoints.
- `betterAuthOptions.baseURL` is hardcoded to `http://127.0.0.1:8787`;
  `BETTER_AUTH_URL` exists in the env but is unused.
- `sessionMiddleware` reads `env` from `cloudflare:workers` instead of using
  `c.env`, unlike every other module.
- `GET /api/get-acc` creates a user on every call and must not ship as-is.
